# Skill: tdd-doc-gen

## Описание
Навык автоматизированной генерации исчерпывающих модульных тестов и обновления документации кода.

## Инструкции (Workflow)
Для любого изменения в функциональном коде (изменение `.py` файлов):

1. **Документирование директорий:** При создании любой новой директории ОБЯЗАТЕЛЬНО создать в ней файл `README.md` на русском языке, описывающий предназначение модуля и принципы его работы.
2. **Анализ влияния (Impact Analysis):** Перед написанием кода или тестов определить все блоки, модули и зависимости, на которые влияет вносимое изменение.
3. **Валидация запуска:** Перед генерацией тестов убедиться, что код работоспособен (запуск минимального smoke-теста).
4. **Генерация тестов (Scenario-based):**
   - Создать/обновить файл теста в директории `tests/`.
   - Тесты **MUST** покрывать:
     - Измененный блок (все комбинации входных параметров, типов данных и граничных условий).
     - Все зависимые блоки, которые могут быть затронуты (регрессионные сценарии).
   - **Обязательно:** Каждый тест должен быть откомментирован максимально подробно, описывая каждый шаг, переменную и ожидаемое состояние.
5. **Запуск и верификация:** Запустить созданные тесты (включая регрессионные). Если тест падает, выполнить отладку до успешного прохождения.
6. **Документирование:** Только после прохождения всех тестов обновить Docstrings в исходном файле, следуя стандарту `hypo69 docblock`.

## Правила
- Не переходить к документированию, если тесты не проходят.
- Тесты должны быть максимально детальными в комментариях (пошаговое описание).
- Всегда следовать `CODE_RULES.md` в части оформления кода и документации.
