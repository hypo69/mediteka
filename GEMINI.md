# GEMINI.md

## 📋 Общие сведения
Этот файл является основным источником проектных инструкций, стандартов и архитектурных соглашений для репозитория `gemini-simplechat`.

## ⚙️ Основные рабочие процессы
Все разработки должны строго соответствовать принципам, описанным в `.ai_instructions/`:
- **Стандарты кода:** Описаны в `rules/CODE_RULES.md`.
- **TDD-документирование:** Для всех функциональных изменений в `.py` файлах ОБЯЗАТЕЛЬНО использование навыка `tdd-doc-gen` (см. протокол в `rules/CODE_RULES.md`).
- **Документация:** Описана в `rules/DOCS_RULES.md`. (Атомарность изменений: документация + код).
- **Медиа-воркфлоу:** Подробно описан в `knowledge/media_organizer_workflow.md`.
- **Принципы торрентов:** Описаны в `knowledge/torrent_and_media_principles.md`.

## 🏗️ Архитектурные требования
- **Explicit is better than implicit:** Передача зависимостей должна быть явной.
- **Fail-Fast:** Использование раннего возврата (`Early Return`).
- **Configuration over Hardcode:** Никаких жестко закодированных параметров; только JSON-конфигурации или переменные окружения.
- **Запрет `None`:** Ключевое слово `None` и проверки `is None` категорически запрещены.
- **Автоматическое версионирование фронтенда (Cache Busting):** При изменении статических файлов (JS, CSS) обязательно увеличивать/обновлять параметр версии (например, `?v=YYYYMMDD` или инкремент) во всех HTML/шаблонах, которые подключают этот файл, чтобы избежать кэширования браузером.
- **Обязательная документация:** Каждая новая директория в проекте ОБЯЗАТЕЛЬНО должна содержать файл `README.md` на русском языке с описанием предназначения модуля и принципов его работы.

## 🛠️ Использование навыков (Skills)
Для выполнения специфических задач используйте доступные системные навыки через инструмент `activate_skill`:
- `skill-creator` — для создания новых навыков.
- `antigravity-support` — для миграции и настройки Antigravity CLI.
- `microsoft-foundry` — для управления Foundry-агентами.

## 📝 Контроль качества (Commit Checklist)
Перед коммитом убедитесь, что:
1. Заголовок файла соответствует стандарту.
2. Публичные функции имеют Docstring в формате `hypo69 docblock`.
3. Код не содержит кириллицы (для Web/PHP-стека).
4. Логирование идет строго через `src.logger.logger`.
5. Все секреты вынесены в `.env`.
6. **Регламент коммитов:** Коммиты выполняются ТОЛЬКО после полной верификации завершенной сессии отладки/разработки. Не коммитьте каждое промежуточное изменение. Коммит должен отражать логически завершенное состояние работоспособного кода.
