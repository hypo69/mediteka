# Media Organizer Plugin

Плагин для управления медиатекой с RAG-поиском через Google Gemini.

## Возможности

- **Управление медиатекой**: хранение метаданных фильмов и сериалов в SQLite
- **RAG-поиск**: семантический поиск по описаниям через Gemini Embedding API
- **Сканирование дисков**: автоматический сбор информации о медиафайлах
- **Генерация отчётов**: создание карточек, аудит, поиск дубликатов
- **FastAPI API**: веб-интерфейс для работы с медиатекой
- **Умное сканирование эпизодов**: пропуск детальной разбивки для длинных сериалов (>15 сезонов или >100 эпизодов)

## Быстрый старт

### Установка зависимостей

```bash
pip install -r requirements.txt
```

Настройте переменные окружения в `.env`:

```
GEMINI_API_KEY=your_api_key_here
```

### Сканирование диска

```bash
py run_media_organizer.py --disk 1 --path D:\Movies
```

### Создание JSON-карточки

```bash
py run_media_organizer.py --title "The Bear"
```

### Пересборка RAG-индекса

```bash
py run_media_organizer.py --rebuild-rag
```

## CLI-команды

| Параметр | Описание |
|----------|----------|
| `--title` | Название фильма/сериала |
| `--type` | Тип: `movie` или `series` |
| `--disk` | Номер диска (1, 2, ...) |
| `--path` | Путь к директории |
| `--force` | Принудительное сканирование |
| `--rebuild` | Пересборка из JSON |
| `--rebuild-rag` | Пересборка RAG-индекса |
| `--web` | Запуск веб-интерфейса |

## API

```python
from plugins.media_organizer import (
    MediaDatabase,
    search_media,
    get_media_card,
    get_random_media,
    ask_with_media_rag,
)

# Подключение к базе
db = MediaDatabase("plugins/media_organizer/data/media.db")

# RAG-поиск
results = search_media("комедии про медведей")

# Случайная рекомендация
card = get_random_media()

# Вопросы о медиатеке
answer = ask_with_media_rag("Порекомендуй что-нибудь")
```

## Умное сканирование эпизодов

Для очень длинных сериалов (например, турецкие сериалы на сотни серий) модель **не строит детальную разбивку на эпизоды**. Это достигается следующей логикой:

1. Сначала загружаются данные о сезонах из TMDB API
2. Если количество сезонов > 15 ИЛИ общее количество эпизодов > 100, или сериал классифицирован как бесконечная драма/мыльная опера, уровень детализации переключается в `overview` (или запрос детальных эпизодов пропускается)
3. Отдельное поле `episodes_detail` в БД больше не используется — все эпизоды и сезоны сохраняются в виде отдельных строк с заполненными полями
4. В поле `episode_scan_skipped` родительского сериала сохраняется `true` для обозначения этого события

Это позволяет:
- Экономить токены и время обработки
- Избежать ошибок при обработке очень больших объёмов данных
- Продолжить работу с другими сериалами, не ожидая разбивки длинных
