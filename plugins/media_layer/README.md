# Media Layer Plugin

Слой маршрутизации медиа-запросов, который автоматически переключает модель в режим медиа-ассистента при упоминании медиа-терминов.

## Связь с другими плагинами

| Плагин | Роль | Взаимодействие |
|--------|------|----------------|
| `media_organizer` | Сбор и хранение медиаданных | Читает данные из `media.db` |
| `telegram_bot` | Взаимодействие с пользователями | Обрабатывает сообщения Telegram |
| `qbittorrent` | Управление торрентами | Может передавать данные о торрентах в медиатеку |

Экосистема плагинов:
- **media_organizer** → собирает, индексирует и хранит метаданные фильмов/сериалов
- **media_layer** → использует эти данные для умного перехвата вопросов
- **telegram_bot** → предоставляет интерфейс взаимодействия
- **qbittorrent** → управляет скачанным контентом

## Возможности

- **Автоматический перехват** вопросов о фильмах, сериалах и медиа-контенте
- **Контекстная инструкция** — модель отвечает только на основе актуальных данных из БД
- **Гибкая система ключевых слов** — поддержка русских и английских медиа-терминов
- **Градиентный отклик** — не MediаLayerPlugin возвращает `None`, запрос продолжает обработку

## Как работает

### Архитектура

```
Пользователь → Telegram/Веб → Core → Media Layer → AI Model
                              ↓ (если ключевые слова найдены)
                         Media Organizer DB (media.db)
```

### Пошаговый процесс

1. **Инициализация при старте**
   ```python
   plugin = MediaLayerPlugin(ai_model)
   # Читает media.db через MediaDatabase.export_all()
   # Сериализует данные в JSON → системная инструкция
   ```

2. **Обработка запроса**
   - Запрос нормализуется (`.lower()`)
   - Проверяются ключевые слова из `_MEDIA_KEYWORDS`
   - Если совпадение есть → формируется полный запрос с инструкцией

3. **Формирование инструкции**
   ```python
   instruction = (
       "Ты — медиа-ассистент. Отвечай ТОЛЬКО на основе данных ниже.\n"
       "Если ответа нет в данных — так и скажи.\n\n"
       "=== МЕДИАТЕКА ===\n"
       "[JSON-данные из media.db]"
   )
   ```

4. **Ответ модели**
   - Если в данных есть информация → модель отвечает по ним
   - Если данных нет → модель говорит "ответа нет"

### Примеры работы

#### Сценарий 1: Вопрос с медиа-ключевым словом
```
Пользователь: "рекомендуй что-нибудь с Дакотой Джонсон"
↓
Media Layer: ключевое слово "рекомендуй" найдено
↓
Model: [получает полную медиатеку в инструкции]
↓
Model: "В вашей медиатеке есть фильмы с Дакотой Джонсон: 
        1. Форсаж 9 (2021) - экшен
        2. Пятьдесят оттенков свободнее (2018) - драма..."
```

#### Сценарий 2: Вопрос без медиа-ключевых слов
```
Пользователь: "какая погода сегодня"
↓
Media Layer: ключевые слова не найдены
↓
Media Layer: возвращает None
↓
Запрос идёт дальше по цепочке других плагинов/ядра
```

## Интеграция с системой

### Загрузка плагина
```python
# plugins/__init__.py
from plugins import load_plugins

plugins = load_plugins(ai_model)
# Автоматически находит media_layer и загружает его
```

### Подключение к цепочке обработки
```python
# core/chat_processor.py (пример)
async def process(message: str) -> str:
    for plugin in plugins.values():
        if result := await plugin.handle(message):
            return result
    return core_response(message)
```

## Обновление данных

### Ручное обновление медиатеки
```bash
py run_media_organizer.py --disk 1 --path D:\Movies
```

### Автоматическое обновление
1. Запустите сканер (`media_organizer`)
2. Данные записываются в `media.db`
3. Перезапустите сервер (или пересоздайте плагин) — `MediaLayerPlugin` автоматически прочитает новые данные

## API и использование

### Программное создание
```python
from plugins.media_layer import MediaLayerPlugin
from src.ai import get_ai_model

ai = get_ai_model()
media_layer = MediaLayerPlugin(ai)

# Проверка медиа-запроса
is_media = media_layer._is_media_query("рекомендуй фильм с Томом Харди")
# True

# Обработка запроса (если нужен прямой вызов)
response = await media_layer._handle("какие фильмы с Марvel?")
```

### Условия срабатывания

Плагин обрабатывает запрос только если:
1. ✅ Файл `media.db` существует
2. ✅ В БД есть хотя бы одна запись
3. ✅ В запросе есть хотя бы одно ключевое слово из `_MEDIA_KEYWORDS`

Если хотя бы одно условие не выполнено — возвращается `None`.

## Ограничения и рекомендации

| Проблема | Решение |
|----------|---------|
| Вес JSON в инструкции | Если БД > 1000 записей — используйте RAG (media_rag.py) |
| Ключевые слова не срабатывают | Проверьте регистр — ключи нормализуются в `_is_media_query()` |
| Старые данные в ответах | Перезапустите сервер после обновления `media.db` |

## Сравнение с RAG-подходом

| Характеристика | Media Layer | Media RAG |
|----------------|-------------|-----------|
| Данные | Полная выгрузка БД | Векторный индекс |
| Мета-данные | Точное соответствие | Семантический поиск |
| Ограничения | ~1000 записей | Тысячи+ записей |
| Запросы | Фактические (кто, когда) | Тематические (похожее,推荐) |
| Латентность | Низкая | Средняя (Embedding API) |

Используйте **Media Layer** для:
- Небольших медиатек (<1000 записей)
- Точных вопросов ("фильмы с актёром X")
- Быстрых ответов без задержек

Используйте **Media RAG** для:
- Больших коллекций (>1000 записей)
- Семантического поиска ("комедии про мотоциклы")
- Сложных запросов с векторными операциями
