# Архитектура RAG ассистента разработчика (FAISS Edition)

## Назначение
Система RAG (Retrieval-Augmented Generation) для ассистента разработчика, предназначенная для быстрого семантического поиска по исходному коду проекта. Использование базы данных (SQLite/PostgreSQL) исключено в пользу файлового индекса FAISS.

## Структура хранения

```
C:\mediateka\src\ai\rag_code_helper\
├── config.json         # Конфигурация: модель, параметры чанков, пути
├── indexer.py          # Логика индексации (FAISS)
├── searcher.py         # Логика поиска (FAISS)
└── rag_index/          # Директория с индексами (в .gitignore)
    ├── code_index.faiss
    ├── metadata.json
    └── chunks.json
```

## Технологический стек
- **Индексация:** [FAISS](https://github.com/facebookresearch/faiss) (Flat L2 index).
- **Эмбеддинги:** Gemini Embedding API (`gemini-embedding-2`).
- **Конфигурация:** JSON-файлы с подстановкой переменных окружения (согласно правилам `CODE_RULES.md`).

## Принципы работы
1. **Индексация:**
   - Чанкинг кода.
   - Генерация эмбеддингов через Gemini.
   - Сохранение индекса в FAISS.
   - Метаданные (пути, строки) хранятся в `metadata.json`.

2. **Поиск:**
   - Генерация эмбеддинга для запроса.
   - Поиск k-ближайших соседей в FAISS.
   - Извлечение соответствующих чанков текста из `chunks.json` по индексам.

## Правила разработки
- Соблюдение `CODE_RULES.md`: отсутствие `None`, использование `src.logger`, docstrings.
- Явная конфигурация через `config.json`.
- Автономность модуля (`src/ai/rag_code_helper/`).
